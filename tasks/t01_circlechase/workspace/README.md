# 实现 CircleChase 回环追踪轨迹

配置为 `Trajectory = "CircleChase, 3000, 5, 2"` 的子弹当前完全不动。

这组参数依次表示：

- `CircleChase`：轨迹类型。
- `3000`：总时长，单位为毫秒。
- `5`：外圈半径，单位为格（1 格 = 64 像素）。
- `2`：内圈半径，单位为格（1 格 = 64 像素）。

请阅读仓库中的代码，补齐 CircleChase 轨迹，使其满足以下行为：

- 子弹向目标飞行，并在目标周围形成回环轨迹。
- `Speed` 的单位是像素/秒；每帧三维位移等于 `Speed * dt / 1000`，Z 轴计入同一速度预算。
- 当目标位于外圈之外（`d > r1`）时，子弹直接向目标逼近。
- 当目标位于外圈与内圈之间（`r2 < d <= r1`）时，抵达节奏由 `totalTime` 决定；径向速度用于在剩余时间内走完剩余距离，余下速度形成切向运动，轨迹应绕目标收拢而不是直接撞上。
- 当目标进入内圈（`d <= r2`）时，继续保持三维速度守恒并收拢追踪，不得停止或把 Z 轴位移加到额外速度上。
- 总时间耗尽后取消回环的时间调度，仍以固定 `Speed` 逐帧追踪当前目标；转向继续受角速度限制，目标移到身后时应在后续帧逐渐转向目标。
- 设子弹到目标的距离为 `d`：当 `r2 < d <= r1` 时，转向角速度上限为 `Speed / 6` 度/秒；其他情况下上限为 `Speed` 度/秒。每帧转过的角度不得超过 `角速度 * dt / 1000`，不能瞬间改变朝向。
- 没有目标时沿当前朝向直线飞行，并且仍应成功启动、持续更新且不崩溃。
- 服务端和客户端必须使用相同的转向规则、角度约定和三维速度分配；在每一帧拿到相同的目标快照、位置、朝向和 `dt` 时，应产生一致的三维轨迹。
- 真实网络中客户端可能比服务端晚收到目标快照。客户端只能根据自己当前持有的快照转向，因此延迟期间允许与服务端轨迹暂时不同；这属于输入延迟，不是两端移动算法可以不同。收到更新快照后，客户端应继续按同一转向限速规则追踪最新目标，不能瞬移到服务端位置。
- 本题不要求修改网络同步链路或自行制造延迟；评测会在相同快照下检查双端算法一致性，交付的 HTML 可额外模拟固定帧延迟来展示上述网络效果。
- 子弹不会因命中目标而停止或销毁，飞行期间应始终保持速度守恒。
